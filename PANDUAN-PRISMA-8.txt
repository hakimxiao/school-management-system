A. PETA PROJECT
---------------
A.1 File dan folder penting
- Sumber model: `prisma/contract.prisma`
- Konfigurasi Prisma dan koneksi: `prisma.config.ts`
- Rahasia koneksi: `.env` (jangan commit atau kirim ke chat)
- Hasil emit contract: `prisma/contract.json` dan `prisma/contract.d.ts`
- Migration: `migrations/app/`
- Snapshot contract: `migrations/snapshots/`
- Client aplikasi: `prisma/db.ts`
- Seed: `prisma/seed.ts`

A.2 Alur umum
Edit contract -> emit -> plan migration -> tinjau -> apply -> status/verify.
Seed adalah langkah terpisah untuk mengisi data contoh; migration tidak berarti
data harus di-seed ulang.

B. VERSI DAN PRASYARAT
----------------------
B.1 Cek versi lokal
    node --version
    npx prisma --version
    npm ls prisma @prisma/orm-postgres

B.2 Catatan kompatibilitas
Project menggunakan `prisma` sebagai CLI dan `@prisma/orm-postgres` sebagai
runtime PostgreSQL. Nomor patch/RC keduanya tidak harus sama. Dokumentasi Prisma
8 yang dirujuk panduan ini mencantumkan Node 22.18+, 24.11+, atau 26+ dan
PostgreSQL 15+ untuk setup ini. Jangan mengganti paket RC dengan versi terbaru
secara membabi buta karena CLI atau API dapat berubah.

C. KONEKSI DATABASE
-------------------
C.1 DATABASE_URL
File `.env` di root project harus mempunyai URL seperti:
    DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/NAMA_DATABASE"

`prisma.config.ts` memuat `.env` melalui `dotenv/config`. Environment variable
`DATABASE_URL` yang sudah ada di terminal dapat mengalahkan nilai dalam `.env`.
Untuk menghapus override hanya dari sesi PowerShell saat ini:
    Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue

C.2 Database di komputer lain
Gunakan IP LAN komputer database sebagai HOST, bukan `127.0.0.1`, `127.0.1.1`,
atau IP internal Docker/WSL. Pastikan PostgreSQL/Docker aktif, port 5432 tersedia,
firewall mengizinkan koneksi, dan kedua komputer berada di jaringan yang dapat
saling menjangkau. Cek dari Windows:
    Test-NetConnection <IP_KOMPUTER_DATABASE> -Port 5432
`TcpTestSucceeded : True` berarti port bisa dijangkau.

C.3 Karakter khusus dan rahasia
URL-encode karakter khusus pada username/password. Contoh: `@` menjadi `%40`,
`:` menjadi `%3A`, `/` menjadi `%2F`, `#` menjadi `%23`, dan `%` menjadi `%25`.
Jangan menempelkan URL asli, password, atau isi `.env` ke panduan, screenshot,
git, atau chat.

D. CONTRACT, MODEL, DAN RELASI
------------------------------
D.1 Bentuk contract project
File Prisma 8 project ini adalah `prisma/contract.prisma`, bukan
`prisma/schema.prisma`. Awali contract dengan:
    // use prisma-8

Contract ini tidak berisi blok `datasource` atau `generator`; konfigurasi
koneksi berada di `prisma.config.ts`.

D.2 Makna field
`String?` berarti kolom nullable. `@id` menetapkan primary key, `@unique`
menetapkan nilai unik, dan `@default(autoincrement())` umum dipakai untuk ID
angka.

D.3 Tipe foreign key
Tipe field foreign key harus sama dengan tipe primary key yang dirujuk. Contoh:
jika `Subject.id` bertipe `Int`, maka `TeacherSubject.subjectId` juga `Int`.
Periksa tipe, nullability, dan pasangan relasi sebelum migration dibuat.

D.4 Many-to-many eksplisit
Project ini memakai model penghubung seperti `TeacherSubject`; pola many-to-many
implisit tidak digunakan. Contoh inti:
    model Teacher {
      id       String @id
      subjects TeacherSubject[]
    }

    model Subject {
      id       Int @id @default(autoincrement())
      name     String @unique
      teachers TeacherSubject[]
    }

    model TeacherSubject {
      teacherId String
      subjectId Int
      teacher   Teacher @relation(fields: [teacherId], references: [id])
      subject   Subject @relation(fields: [subjectId], references: [id])
      @@id([teacherId, subjectId])
    }
Pada pola ini, `teacher.subjects` berisi record `TeacherSubject`.

D.5 Catatan model project
- `Attendance.lessonId` bertipe `Int`, sesuai `Lesson.id`.
- `Lesson` memiliki satu `Subject` melalui `subject`.
- `Result.examId` dan `Result.assignmentId` dapat nullable (`Int?`) bila hasil
  hanya terkait salah satu jenis penilaian.
- Ejaan enum hari yang benar adalah `THURSDAY`.
- `TeacherSubject.subjectId` bertipe `Int`.
- `Class` memiliki `supervisorId` yang merujuk guru dan `gradeId` yang merujuk
  grade.

E. EMIT CONTRACT
----------------
E.1 Kapan menjalankan emit
Setiap kali `prisma/contract.prisma` berubah, jalankan:
    npx prisma contract emit

Perintah ini memvalidasi contract dan memperbarui `contract.json` (metadata model
untuk runtime/migration) serta `contract.d.ts` (tipe TypeScript). Jangan edit
kedua hasil emit secara manual; simpan perubahan hasil emit bersama sumbernya.

E.2 Error relasi
Jika muncul `PSL_ORPHANED_BACKRELATION`, periksa relasi balik pada kedua model.
Untuk many-to-many gunakan model penghubung eksplisit.

F. MIGRATION HARIAN
-------------------
F.1 Ubah contract lalu emit
Edit `prisma/contract.prisma`, kemudian:
    npx prisma contract emit

F.2 Rencanakan migration
    npx prisma migration plan --name nama_perubahan

Perintah ini membuat paket lokal di `migrations/app/<timestamp>_<nama>/` dan
tidak menerapkan perubahan ke database.

F.3 Jika planner meminta origin
Jika muncul `MIGRATION.PLAN_ORIGIN_UNKNOWN`, jangan mengulangi plan tanpa
parameter. Lihat Bagian G untuk memilih origin migration yang sesuai. Jangan
meneruskan dengan asumsi database kosong jika migration sudah ada di disk.

G. ORIGIN MIGRATION DAN REF DB
-----------------------------
G.1 Arti origin
Planner perlu tahu contract asal sebelum membandingkannya dengan contract baru.
Biasanya origin disimpan sebagai ref bernama `db`. Jika migration sudah ada di
disk tetapi ref `db` tidak tersedia, planner menolak fallback ke database kosong
karena itu dapat membuat rencana yang membangun ulang semua tabel.

G.2 Cek status database terlebih dahulu
    npx prisma migration status

Status memperlihatkan migration yang sudah diterapkan dan apakah database up to
date. Untuk melihat opsi yang didukung CLI lokal:
    npx prisma migration plan --help

G.3 Tentukan origin eksplisit
Jika status menunjukkan baseline yang diterapkan, gunakan nama folder migration
itu sebagai `--from`. Contoh baseline project ini:
    npx prisma migration plan --from 20261111T0813_setuptable --name Class_Model_Fix

Nama folder tersebut diterima sebagai contract reference. Opsi `--from` membuat
asal plan jelas; opsi itu sendiri tidak mengubah database atau memperbaiki
ketidakcocokan database.

G.4 Baseline project saat ini
Migration awal project adalah `migrations/app/20261111T0813_setuptable/`.
Metadata migration menunjukkan contract asal kosong (`from: null`) dan contract
tujuannya berawalan `3f4c8da`. Pada database yang sudah menerapkan baseline ini,
status dapat menampilkan baris `20261111T0813_setuptable ∅ → 3f4c8da ✓ applied`.
Dalam kondisi itu, gunakan baseline tersebut sebagai `--from` untuk perubahan
berikutnya. Jangan hapus atau tulis ulang migration yang sudah diterapkan.

H. MENINJAU DAN MENERAPKAN MIGRATION
-----------------------------------
H.1 Tinjau plan
Setelah plan menghasilkan folder migration, buka detailnya:
    npx prisma migration show <folder-migration>

Periksa nama tabel/kolom, tipe, foreign key, nullability, dan operasi yang
mengubah atau membuang data. Jika plan tidak benar, jangan apply. Perbaiki
contract, emit ulang, lalu rencanakan ulang migration yang belum pernah
diterapkan. Jangan menghapus migration yang sudah diterapkan di database lain.

H.2 Terapkan setelah plan benar
    npx prisma db migrate --advance-ref db

Perintah ini yang menerapkan migration. `--advance-ref db` memajukan ref
pengembangan setelah apply. Gunakan database development untuk eksperimen; jangan
menunjuk database production tanpa prosedur deployment yang disepakati.

H.3 Verifikasi
    npx prisma migration status
    npx prisma db verify

Status memeriksa riwayat migration; `db verify` membandingkan contract dengan
struktur database. Keduanya menghubungi database untuk pemeriksaan.

I. RELASI BALIK TANPA PERUBAHAN DATABASE
----------------------------------------
I.1 Contoh `Class.students`
Jika model `Student` sudah mempunyai `classId Int` dan relasi `class Class`,
menambahkan daftar balik berikut pada `Class`:
    students Student[]

membuat relasi itu dapat diakses dari sisi `Class`. Foreign key tetap berada
pada `Student.classId`; kolom dan data penyimpanan tidak berubah. Karena itu
penambahan relasi balik saja tidak membutuhkan migration dan tidak menghapus
atau membuat ulang record Student.

I.2 Mengapa plan bisa mengatakan “No changes detected”
Setelah emit, jika hash contract tujuan sama dengan hash origin (misalnya
`from: 3f4c8da...` dan `to: 3f4c8da...`), planner tidak menemukan perubahan
storage yang perlu dimigrasikan. Ini wajar untuk relasi balik seperti
`Class.students`. Jalankan `npx prisma db verify` untuk memastikan contract dan
database cocok. Tidak perlu menjalankan `db migrate` atau seed ulang untuk
perubahan relasi balik ini.

I.3 Kapan migration dibutuhkan
Migration dibutuhkan jika contract mengubah struktur penyimpanan, misalnya
menambah/menghapus kolom, mengubah tipe, nullability, default, constraint, atau
relasi foreign key. Jika planner tidak melihat perubahan padahal Anda mengubah
field penyimpanan, pastikan contract yang benar telah diedit dan `contract emit`
berhasil sebelum membuat plan.

J. DATABASE BARU
----------------
J.1 Database development benar-benar kosong
    npx prisma contract emit
    npx prisma db init
    npx prisma db verify

`db init` membuat struktur sesuai contract pada database kosong dan menandai
contract yang sesuai. Untuk riwayat yang dapat diulang di environment lain,
rencanakan dan commit baseline migration juga.

J.2 Pastikan target benar
Periksa `DATABASE_URL` dan nama database sebelum perintah yang menulis. Jangan
menjalankan `db init` pada database berisi tabel/data tanpa memahami dampaknya.

K. DATABASE YANG SUDAH BERISI DATA
----------------------------------
K.1 Belum dikelola Prisma 8
Jangan jalankan `db init` sembarangan. Contract harus mencerminkan struktur
database yang ada. Jika struktur sudah persis cocok, prosedur `db sign` dapat
menandai contract tanpa mengubah tabel. Jika belum cocok, buat dan tinjau plan
yang sesuai sebelum menerapkan perubahan.

K.2 Database dengan riwayat migration lama
Jika sebelumnya dikelola Prisma 7, ikuti prosedur upgrade resmi agar riwayat
migration lama tidak terputus. Jangan membuat baseline baru sebelum memeriksa
riwayat dan status database.

L. UPDATE DATABASE LANGSUNG
---------------------------
Untuk menyelaraskan database development langsung tanpa menyimpan perubahan
sebagai migration:
    npx prisma contract emit
    npx prisma db update --dry-run
    npx prisma db update

Gunakan `db update` hanya jika perubahan langsung memang diinginkan. Untuk alur
tim dan deployment, gunakan migration yang ditinjau lalu diterapkan. Tinjau
dry-run terlebih dahulu; `db update` bukan cara aman untuk menghapus data.

M. SEED DATA
------------
M.1 Kegunaan dan perintah
Seed mengisi data contoh untuk mencoba aplikasi. Script project ada di
`prisma/seed.ts`; jalankan dari root:
    npm run db:seed

Script memakai `dotenv/config`, runtime `@prisma/orm-postgres`, dan
`prisma/contract.json`. Prisma 8 RC project ini belum memakai perintah bawaan
`prisma db seed`. Node menjalankan TypeScript melalui
`--experimental-strip-types`; gunakan Node yang didukung project (saat panduan
ini disusun Node 24.19). Tidak diperlukan `prisma generate` atau
`@prisma/client` Prisma 7. Script menutup client dengan `db.close()`.

M.2 Urutan setup database development baru
1. Pastikan PostgreSQL aktif dan `.env` menunjuk database development yang benar.
2. Emit contract jika contract berubah: `npx prisma contract emit`.
3. Buat struktur database dengan `db init` untuk database kosong atau dengan
   migration yang sudah ditinjau (Bagian F-H).
4. Pastikan contract cocok: `npx prisma db verify`.
5. Isi contoh data: `npm run db:seed`.

M.3 Kapan seed tidak perlu diulang
Migration mengubah struktur database; seed mengisi record contoh. Perubahan
contract tidak otomatis mengharuskan seed ulang. Jika data contoh sudah ada dan
perubahan hanya menambah relasi balik seperti `Class.students`, record yang ada
tetap dapat digunakan dan tidak perlu dibuat ulang. Verifikasi database, lalu
lanjutkan memakai data yang ada.

Seed ulang hanya jika memang ingin mengisi data contoh pada database yang
kosong/baru atau setelah database development sengaja disiapkan ulang. Jangan
seed production.

M.4 Sifat seed saat ini
Seed ini bukan idempotent: menjalankannya berulang dapat gagal pada unique
constraint (`username`, `email`, atau `name`). Insert dilakukan berurutan dan
bukan dalam satu transaction, sehingga kegagalan di tengah dapat meninggalkan
sebagian record. Periksa error dan database sebelum mengulang. Untuk memulai
ulang, gunakan database development kosong atau bersihkan data secara terencana;
jangan menghapus data production.

M.5 Isi dan relasi seed
Seed saat ini membuat 2 Admin, 6 Grade, 6 Class, 10 Subject, 15 Teacher,
30 Lesson, 25 Parent, 50 Student, serta 10 Exam, Assignment, Result, dan
Attendance; juga 5 Event dan 5 Announcement.
- Buat record induk sebelum anak yang memiliki foreign key.
- `Class` memerlukan `supervisorId`; seed menetapkan guru supervisor.
- Teacher-Subject menggunakan model join `TeacherSubject` dengan `teacherId`
  dan `subjectId`.
- Contract Student dan Teacher saat ini tidak punya field `birthday`.
- ID angka dihasilkan database; seed mengasumsikan database kosong dan urutan
  ID sesuai urutan seed.

M.6 Mengubah seed
1. Periksa field wajib, enum, tipe, dan relasi pada contract.
2. Jika contract berubah, emit dan terapkan perubahan struktur terlebih dahulu.
3. Edit `prisma/seed.ts`; buat data menurut urutan foreign key.
4. Untuk pemeriksaan tipe sesuai alur project, jalankan `npx tsc --noEmit`.
5. Jalankan seed hanya pada database development yang benar dan tinjau hasilnya
   lewat Studio atau query aplikasi.

N. PRISMA STUDIO
----------------
N.1 Jalankan dari package project
Untuk membuka Studio dari root project:
    npm run db:studio

Script `scripts/db-studio.mjs` membaca `DATABASE_URL` dari `.env`, memeriksa
bahwa nilainya ada, lalu menjalankan `npx prisma@prev studio --url=...` dari
folder induk project. URL tidak perlu ditempel di perintah. Pertama kali, npx
mungkin meminta izin mengunduh paket; jawab `y`.

N.2 Buka dan hentikan Studio
Buka alamat yang dicetak terminal, biasanya `http://localhost:5555`. Jika port
sedang digunakan, ikuti port yang benar-benar dicetak. Biarkan terminal tetap
berjalan saat Studio digunakan; tekan Ctrl+C untuk menghentikannya.

N.3 Catatan CLI
`npx prisma studio` pada CLI Prisma 8 RC project ini belum tersedia. CLI
terpisah `prisma@prev` dipakai untuk Studio dan tidak mengganti CLI migration
lokal. Menjalankannya dari folder induk menghindari pembacaan
`prisma.config.ts` project oleh CLI Studio.

O. QUERY APLIKASI
-----------------
Client disiapkan di `prisma/db.ts`. Contoh query server-side:
    import { db } from "@/prisma/db";

    const students = await db.orm.public.Student
      .orderBy((student) => student.name.asc())
      .take(20)
      .all();

    const student = await db.orm.public.Student
      .where({ username: "student01" })
      .first();

`.all()` mengembalikan daftar; `.first()` mengembalikan satu baris atau `null`.
PostgreSQL menggunakan namespace `public` secara default. Jalankan query di
server (misalnya Server Component atau route handler), jangan mengekspos akses
database langsung dari browser.

Q. PEMECAHAN MASALAH
--------------------
Q.1 `MIGRATION.PLAN_ORIGIN_UNKNOWN`
Migration ada di disk, tetapi planner tidak menemukan ref `db` dan origin tidak
diberikan. Cek `npx prisma migration status`, lalu gunakan migration folder
terakhir yang memang menjadi kondisi awal, misalnya:
    npx prisma migration plan --from 20261111T0813_setuptable --name perubahan
Jangan memilih `@empty` jika database sudah memiliki migration dan data.

Q.2 `No changes detected`
Pastikan `contract emit` dijalankan setelah mengubah contract. Jika hash `from`
dan `to` sama, tidak ada perubahan struktur tersimpan untuk dimigrasikan. Ini
wajar untuk relasi balik saja. Jalankan `npx prisma db verify`; seed ulang tidak
diperlukan untuk perubahan tersebut.

Q.3 Koneksi gagal
`ECONNREFUSED 127.0.0.1/127.0.1.1:5432`: URL masih menunjuk loopback. Periksa
HOST, override `DATABASE_URL`, Docker port mapping, dan firewall.

`ECONNREFUSED <IP>:5432` atau `Test-NetConnection` gagal: PostgreSQL tidak
menerima koneksi. Periksa service/container, port publish, firewall, jaringan,
dan alamat IP.

Error autentikasi atau host tidak ditemukan: periksa nama database/user/password,
URL-encoding karakter khusus, dan pastikan terminal tidak punya override lama.

Q.4 Error contract atau migration
`PSL_ORPHANED_BACKRELATION` atau tipe foreign key salah: periksa kedua sisi
relasi, samakan tipe foreign key dan primary key, dan gunakan join model untuk
many-to-many.

`db verify` gagal: bandingkan contract, migration yang diterapkan, dan struktur
database. Jangan gunakan `db sign` untuk menutupi perbedaan; `db sign` hanya
untuk database yang memang sudah cocok.

Q.5 Error seed
Tabel tidak ditemukan / `relation does not exist`: schema belum dibuat,
migration belum diterapkan, atau URL menunjuk database lain. Terapkan setup dan
jalankan `npx prisma db verify` sebelum seed.

Duplicate key / unique constraint: seed mungkin sudah pernah berjalan. Periksa
record yang sudah masuk; seed bukan upsert dan tidak aman dijalankan berulang.

Foreign key / referenced record tidak ada: buat record induk lebih dulu dan
pastikan ID relasi merujuk record yang benar.

TypeScript menyebut field tidak dikenal seperti `birthday` atau `subjects`:
sesuaikan seed dengan contract Prisma 8. Relasi teacher-subject memakai model
`TeacherSubject`, bukan API `connect` Prisma 7.

`ERR_MODULE_NOT_FOUND` untuk `./db`: pastikan seed project terbaru digunakan.
Node yang menjalankan TypeScript ESM langsung memerlukan ekstensi pada import
lokal. Seed project membuat client dari runtime dan contract JSON; jangan
mengembalikan import extensionless `./db`.

`MODULE_TYPELESS_PACKAGE_JSON`: pada Node 24 ini peringatan bahwa package belum
menyatakan `type: module` dan Node mendeteksi sintaks ESM. Peringatan itu sendiri
tidak menghentikan seed. Jangan menambah `"type": "module"` hanya untuk
menghilangkannya tanpa mengecek dampaknya pada Next.js dan tooling.

`CLI.UNKNOWN_COMMAND` untuk Studio: gunakan `npm run db:studio`.

R. ALUR HARIAN RINGKAS
----------------------
R.1 Mengubah contract
1. Edit `prisma/contract.prisma`.
2. Jalankan `npx prisma contract emit`.
3. Cek `npx prisma migration status` jika origin belum jelas.
4. Plan migration; jika perlu, berikan `--from <nama-folder-migration>`.
5. Tinjau migration dengan `npx prisma migration show <folder>`.
6. Jika operasi benar, terapkan dengan `npx prisma db migrate --advance-ref db`.
7. Jalankan `npx prisma migration status` dan `npx prisma db verify`.
8. Seed hanya bila ingin mengisi data contoh dan database development memang
   perlu diisi; jangan seed ulang hanya karena contract berubah.

R.2 Menyimpan perubahan ke git
Commit contract, hasil emit, migration baru, dan perubahan seed jika ada.
Jangan commit `.env`. Jangan menghapus atau menulis ulang migration yang sudah
diterapkan pada database bersama.

U.1 Pastikan target database
Periksa nama database pada URL lokal tanpa menyalin URL/password ke chat atau
log. Pastikan terminal tidak memakai override `DATABASE_URL` yang keliru.

U.2 Pahami dampak perintah
`contract emit` dan `migration plan` menyiapkan file lokal. `db migrate`,
`db init`, `db update`, serta `db:seed` menulis ke database. Tinjau plan dan
pastikan target database sebelum menjalankan perintah yang menulis.

V. MEMBACA MIGRATION STATUS
---------------------------
V.1 Applied dan up to date
Baris `✓ applied` berarti migration itu sudah diterapkan. `Up to date` berarti
database sudah sampai pada state migration yang diketahui CLI.

V.2 Ref `@db` dan contract hash
Status dapat menampilkan hash contract diikuti `@contract @db`. Cocokkan hash
dengan baris migration untuk mengetahui state database. Jika planner tetap
meminta origin eksplisit, gunakan nama folder migration yang diterapkan pada
`--from`, seperti dijelaskan di Bagian G.

W. MEMBACA HASIL MIGRATION PLAN
-------------------------------
W.1 `No changes detected`
Plan tidak membuat perubahan database. Bandingkan nilai `from` dan `to`; jika
sama, contract hasil emit sama dengan origin. Relasi balik tanpa kolom foreign
key baru memang tidak memerlukan operasi penyimpanan.

W.2 Ada operasi perubahan
Tinjau setiap operasi di `migration show`. Pastikan kolom, tipe, nullability,
constraint, rename, backfill, dan potensi kehilangan data memang sesuai. Jangan
apply hanya karena plan berhasil dibuat.

X. SEED DAN DATA CONTOH
-----------------------
X.1 Data contoh sudah ada
Jangan menjalankan seed kembali hanya untuk perubahan contract. Jika database
sudah berisi data dan perubahan hanya menambah akses relasi, data tersebut tetap
tersedia. Verifikasi schema dan lanjutkan menggunakan data yang ada.

X.2 Memang perlu mengulang seed
Seed project saat ini bukan idempotent. Gunakan database development kosong
atau siapkan ulang database secara sadar setelah memastikan data yang boleh
dihapus. Jangan menjalankan penghapusan data production.

Y. DAFTAR PERINTAH SIAP PAKAI

    npx prisma migration status
    npx prisma migration plan --from 20261111T0813_setuptable --name nama_perubahan

    npm run db:studio

Y.3 Bantuan CLI

    npx prisma migration plan --help
    npx prisma db migrate --help

Z. CATATAN AKHIR PROJECT
------------------------
Z.1 File sumber yang benar
Gunakan `prisma/contract.prisma` sebagai contract. Jika catatan lama di
`prisma-8.md` menyebut `schema.prisma`, sesuaikan dengan struktur project ini.

Z.2 Migration bersama
Simpan migration yang sudah diterapkan. Jangan menghapus atau menulis ulang
migration yang telah digunakan oleh database lain. Commit contract, hasil emit,
migration baru, dan perubahan seed yang memang dilakukan; jangan commit `.env`.
